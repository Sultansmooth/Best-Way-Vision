## Implementation Details

### Save Triggers:
- **Cameras**: Saved on create, update, delete
- **Zones**: Saved on create, update, delete
- **Email Config**: Saved on "Save Configuration" button click
- **Auth**: Saved on successful login, removed on logout

### Data Loading:
- All data loads automatically when the app initializes
- `typeof window !== 'undefined'` checks ensure code only runs in browser
- Date objects are re-instantiated from stored ISO strings
- Invalid/corrupted data is caught and logged to console

### Backend Migration Path:
All localStorage operations are centralized in:
- `/frontend/src/lib/api.ts` - Events and email config
- `/frontend/src/lib/feeds-api.ts` - Cameras and zones
- `/frontend/src/contexts/auth-context.tsx` - Authentication

To connect to backend:
1. Replace `localStorage.getItem()` with `fetch()` calls
2. Replace `localStorage.setItem()` with POST/PUT API calls
3. Update type definitions as needed
4. Add error handling for network failures

## Troubleshooting

### Data Not Persisting:
1. Check browser console for errors
2. Verify localStorage is not disabled in browser settings
3. Check if in private/incognito mode (localStorage may be restricted)
4. Verify localStorage quota not exceeded (usually 5-10MB)

### Corrupted Data:
1. Open DevTools → Application → Local Storage
2. Delete the corrupted key
3. Refresh the page (app will start fresh)

### Testing in Development:
- Dev server (port 3000) and Docker (port 3001) use separate localStorage
- Data saved on one port won't appear on the other
- Use same port consistently for testing
